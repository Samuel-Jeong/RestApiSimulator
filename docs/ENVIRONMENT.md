# Environment Variables and Pre-request Scripts

## Overview

REST API Simulator supports Postman-like environment variables and pre-request scripts for dynamic test configuration and data preparation.

## Features

### 1. Environment Variables

Environment variables allow you to:
- Store configuration for different environments (dev, staging, prod)
- Reuse values across multiple scenarios
- Switch between environments without modifying scenarios
- Keep sensitive data separate from scenario files

### 2. Pre-request Scripts

Pre-request scripts enable you to:
- Generate dynamic values before test execution
- Fetch authentication tokens
- Prepare test data
- Calculate derived values
- Set request-specific variables

## Directory Structure

```
projects/
  your_project/
    config/
      hosts.json              # Host configurations
    env/                      # Environment configurations
      development.json
      staging.json
      production.json
    package_library/          # Pre-request scripts
      pre_request.py
      auth_helper.py
    scenario/                 # Test scenarios
      success/

```

## Environment Configuration

### File Format

Environment files are JSON files stored in the `env/` folder:

```json
{
  "name": "development",
  "variables": {
    "base_url": "https://api.dev.example.com",
    "api_key": "dev-api-key-123456",
    "tenant_id": "tenant-dev-001",
    "timeout": 30,
    "user_id": 1,
    "username": "dev_user",
    "email": "dev@example.com"
  }
}
```

### Variable Types

Environment variables support all JSON types:
- **String**: `"api.example.com"`
- **Number**: `30`, `3.14`
- **Boolean**: `true`, `false`
- **Object**: `{"key": "value"}`
- **Array**: `[1, 2, 3]`

### Using Environment Variables in Scenarios

Reference environment variables using the `{{env.variable_name}}` syntax:

```json
{
  "name": "Get User Test",
  "steps": [
    {
      "method": "GET",
      "path": "/api/users/{{env.user_id}}",
      "headers": {
        "X-API-Key": "{{env.api_key}}",
        "X-Tenant-ID": "{{env.tenant_id}}"
      },
      "assertions": [
        {
          "field": "status",
          "operator": "eq",
          "value": 200
        }
      ]
    }
  ]
}
```

## Pre-request Scripts

### Basic Structure

Pre-request scripts are Python files in the `package_library/` folder:

```python
"""
Pre-request script

Available variables:
- env: Environment variables (dict)
- vars: Scenario variables (dict)
- result: Dictionary to store results
"""

import time
from datetime import datetime

# Generate timestamp
result['timestamp'] = int(time.time())
result['datetime'] = datetime.now().isoformat()

# Generate authentication token
if 'api_key' in env:
    result['auth_token'] = f"Bearer {env['api_key']}"

# Set dynamic values
result['request_id'] = f"req-{result['timestamp']}"
```

### Available Context

Pre-request scripts have access to:

1. **env**: Environment variables dictionary
2. **vars**: Scenario variables dictionary  
3. **result**: Output dictionary (results are merged into scenario variables)

### Example: Token Generation

```python
"""Generate authentication token"""

import hashlib
import time

# Simulate token generation
api_key = env.get('api_key', '')
timestamp = str(int(time.time()))

token_string = f"{api_key}:{timestamp}"
token_hash = hashlib.sha256(token_string.encode()).hexdigest()

result['auth_token'] = f"Bearer {token_hash[:32]}"
result['timestamp'] = timestamp

print(f"Generated auth token: {result['auth_token'][:20]}...")
```

### Example: Dynamic Data Preparation

```python
"""Prepare test data"""

import random
from datetime import datetime, timedelta

# Generate test user data
user_id = random.randint(1000, 9999)
result['test_user_id'] = user_id
result['test_username'] = f"test_user_{user_id}"
result['test_email'] = f"test{user_id}@example.com"

# Generate test dates
now = datetime.now()
result['start_date'] = (now - timedelta(days=7)).isoformat()
result['end_date'] = now.isoformat()

# Generate test resource
result['resource_name'] = f"test_resource_{int(now.timestamp())}"
```

## Variable Resolution

### Resolution Order

Variables are resolved in the following order:

1. **Scenario variables** (defined in scenario file)
2. **Pre-request results** (generated by pre-request script)
3. **Environment variables** (from selected environment)

Later definitions override earlier ones.

### Variable Syntax

Use double curly braces to reference variables:

- `{{variable_name}}` - Direct variable reference
- `{{env.variable_name}}` - Environment variable
- `{{result.variable_name}}` - Pre-request result

### Nested Variables

Variables can be nested in objects:

```json
{
  "body": {
    "user": {
      "id": "{{env.user_id}}",
      "name": "{{test_username}}",
      "email": "{{env.email}}"
    },
    "metadata": {
      "timestamp": "{{timestamp}}",
      "environment": "{{env.name}}"
    }
  }
}
```

### Variable in URL Paths

```json
{
  "path": "/api/users/{{env.user_id}}/profile"
}
```

### Variable in Headers

```json
{
  "headers": {
    "Authorization": "{{auth_token}}",
    "X-API-Key": "{{env.api_key}}",
    "X-Request-ID": "{{request_id}}"
  }
}
```

Pre-request scripts are automatically executed if:
1. An environment is selected
2. A file named `pre_request.py` exists in `package_library/`

Execution happens before scenario starts.

## Best Practices

### 1. Environment Separation

Create separate environment files for each stage:

```
env/
  development.json
  staging.json
  production.json
```

### 2. Sensitive Data

Never commit sensitive tokens to version control:

```json
{
  "name": "production",
  "variables": {
    "api_key": "REPLACE_WITH_ACTUAL_KEY",
    "secret": "REPLACE_WITH_ACTUAL_SECRET"
  }
}
```

Consider using environment-specific `.gitignore`:

```
env/production.json
env/staging.json
```

### 3. Variable Naming

Use clear, descriptive names:

```json
{
  "base_url": "https://api.example.com",
  "api_key": "dev-key-123",
  "tenant_id": "tenant-001"
}
```

### 4. Pre-request Organization

For complex logic, create multiple helper scripts:

```
package_library/
  pre_request.py       # Main pre-request script
  auth_helper.py       # Authentication utilities
  data_generator.py    # Test data generation
```

Import helpers in `pre_request.py`:

```python
from auth_helper import generate_token
from data_generator import create_test_user

result['auth_token'] = generate_token(env['api_key'])
result['test_user'] = create_test_user()
```

### 5. Error Handling

Handle missing variables gracefully:

```python
# In pre-request script
api_key = env.get('api_key')
if not api_key:
    print("Warning: api_key not found in environment")
    result['auth_token'] = "Bearer default-token"
else:
    result['auth_token'] = f"Bearer {api_key}"
```

## Troubleshooting

### Variable Not Resolving

Check:
1. Variable name matches exactly (case-sensitive)
2. Environment is selected
3. Variable exists in environment file
4. Syntax is correct: `{{env.variable_name}}`

### Pre-request Script Error

Check:
1. Script has no syntax errors
2. All required imports are available
3. Script returns results in `result` dictionary
4. Script is named `pre_request.py`

### Environment Not Loading

Check:
1. File is in `env/` folder
2. File has `.json` extension
3. JSON is valid
4. File includes `name` and `variables` fields

## API Reference

### VariableResolver

Resolves variables in strings and data structures.

**Methods:**
- `resolve(value)` - Resolve variables in any value type
- `add_variables(dict)` - Add or update variables
- `has_unresolved_variables(text)` - Check for unresolved variables

### PreRequestEngine

Executes pre-request scripts.

**Methods:**
- `execute_script(name, env_vars, scenario_vars)` - Execute script
- `has_script(name)` - Check if script exists
- `list_scripts()` - List available scripts

### ProjectManager

**Methods:**
- `list_environments(project)` - List environments
- `load_environment(project, name)` - Load environment
- `save_environment(project, name, env)` - Save environment
- `get_package_library_path(project)` - Get package_library path
